B2B Lead Builder Next — دليل التثبيت والتطوير

الملفات
- app_next.py: التطبيق الجديد.
- requirements.txt: المكتبات التي يثبتها Streamlit.

مهم
- احتفظ بتطبيقك الحالي كما هو، ولا تحذف app.py أو app_auto.py أو app_pro.py.
- هذه النسخة تضيف ميزات، لكنها لا تعني أن كل بيانات Apollo أو Findymail متاحة مجانًا.
- لا تضع مفاتيح API داخل GitHub أو داخل ملفات الكود.

الميزات الموجودة في هذه النسخة
1) بحث مجاني عن سجلات شركات عامة عبر Wikidata.
2) بحث عن الأشخاص عبر Apollo People Search API الرسمي إذا أدخلت مفتاح API صالحًا في الشريط الجانبي. الوصول يتوقف على خطة/صلاحية حساب Apollo؛ البحث لا يعيد بريدًا أو هاتفًا مضمونًا.
3) فلاتر للبلد، والكلمات المفتاحية، والمسمى الوظيفي، ومستوى الأقدمية، وحجم الشركة، والصناعة (في Apollo يجب أن تطابق الصناعة تصنيف Apollo الرسمي).
4) استيراد ملفات CSV وExcel، وتوحيد أسماء الأعمدة، ودمج السجلات وحذف التكرارات المعروفة.
5) خيار اختياري للعثور على الإيميلات الناقصة أو التحقق من البريد الحالي باستخدام Findymail. قد يستهلك أرصدة من حسابك. لا يعمل إلا بعد وضع مفتاحك في الحقل وتحديد الموافقة.
6) درجة اكتمال البيانات، ومصدر السجل، وتاريخ الجمع، وروابط البحث.
7) جدول داخل التطبيق وتنزيل Excel منسق مع ورقة Summary أو تنزيل CSV.
8) واجهة عربية/إنجليزية.

طريقة رفع النسخة الجديدة إلى GitHub
1) نزّل ZIP وفك الضغط على جهازك.
2) افتح مستودع GitHub الحالي: mina-lead-generation.
3) اضغط Add file ثم Upload files.
4) ارفع app_next.py وrequirements.txt إلى الصفحة الرئيسية للمستودع. لا ترفع ZIP نفسه.
5) اضغط Commit changes.
6) لا تحذف التطبيق الحالي أو ملفاته. اترك النسخة الجديدة باسم منفصل.

طريقة تشغيل النسخة الجديدة على Streamlit
1) افتح https://share.streamlit.io/deploy
2) أنشئ تطبيقًا جديدًا من مستودعك.
3) Repository: اختر مستودع mina-lead-generation مع اسم حسابك.
4) Branch: main
5) Main file path: app_next.py
6) اضغط Deploy وانتظر حتى ينتهي تثبيت المكتبات.

طريقة التجربة المجانية أولًا
1) افتح التطبيق الجديد.
2) اختر وضع «الشركات — مصدر عام مجاني».
3) اكتب Egypt في الدولة، وsoftware في الكلمة المفتاحية، و100 في حد النتائج.
4) اضغط «ابحث ونظّف النتائج»، ثم نزّل Excel أو CSV.

بحث الأشخاص عبر Apollo (اختياري)
- أنشئ/افتح حساب Apollo واطلب API key من Settings > Integrations > API Keys، إن كان الحساب مؤهلًا.
- في التطبيق اكتب مفتاحك في حقل Apollo API key في الشريط الجانبي، واختر «الأشخاص — Apollo API».
- اكتب الدولة والمسمى الوظيفي وحد النتائج ثم اضغط البحث.
- حسب توثيق Apollo، People API Search لا يستهلك أرصدة بحث، لكن الوصول قد يتطلب بريد عمل وصلاحيات حساب مناسبة؛ ولا يعيد هذا endpoint البريد أو الهاتف. بعض أسماء العائلة تكون مخفية جزئيًا في نتائج البحث.

العثور على البريد أو التحقق منه عبر Findymail (اختياري)
- لا تستخدم هذه الوظيفة إلا إذا كان لديك مفتاح صالح وتقبل احتمال خصم الأرصدة.
- اكتب المفتاح في حقل Findymail API key، ثم افتح قسم إثراء البريد.
- اختر العثور على الإيميلات الناقصة أو التحقق من الإيميلات الموجودة، وحدد حدًا صغيرًا (10) للتجربة.
- اقرأ تحذير الأرصدة، وضع علامة الموافقة، ثم اضغط تشغيل العملية.
- العثور على البريد يتطلب اسم شخص كاملًا ونطاق موقع الشركة؛ لن يتم البحث عن الاسم إذا كان ناقصًا أو مخفيًا جزئيًا. حالة «تم العثور عليه» ليست بديلًا عن حالة تحقق صريحة من مزود البيانات.

حماية المفاتيح والخصوصية
- لا تلصق المفتاح في GitHub أو في README أو أي ملف كود.
- استخدم مفاتيحك فقط على تطبيق تتحكم في رابطه والوصول إليه. لا تضع مفتاحًا شخصيًا في Secrets لتطبيق عام يستطيع أي شخص تشغيل أزراره، لأن الزوار قد يتسببون في استخدام حسابك.
- المفاتيح تُكتب في حقول كلمة مرور داخل الجلسة ولا تُصدّر في ملفات النتائج؛ مع ذلك، لا تستخدم خدمة عامة لا تثق بها لمعالجة بيانات حساسة.
- لا ترفع بيانات عملاء سرية إلى مستودع GitHub عام.

حدود معروفة
- Wikidata مصدر عام مفيد لكنه ليس دليلًا شاملًا لكل الشركات في العالم، وقد يعيد نتائج ناقصة أو يرفض استعلامًا واسعًا بسبب حدود الخدمة.
- Google/X-Ray يولّد روابط بحث فقط؛ التطبيق لا يحمّل نتائج Google تلقائيًا.
- لا يتم كشط LinkedIn أو تشغيل روبوت على حسابك.
- البحث في Apollo لا يكفي لإظهار كل تفاصيل الاتصال؛ إثراء البريد أو الهاتف قد يحتاج endpoint منفصلًا وقد يكون مدفوعًا.
- Findymail وLusha وKaspr وApollo وغيرها مزودون مستقلون؛ تراخيصهم وأسعارهم وحدود استخدامهم مختلفة.
- درجة الاكتمال تقيس نسبة الحقول المملوءة، وليست إثباتًا أن البيانات صحيحة.
- التطبيق الحالي لا يحفظ كل قوائمك في قاعدة بيانات دائمة؛ نزّل ملفاتك بعد كل جلسة.

خطة التطوير المقترحة
المرحلة 1 — هذه النسخة: مصادر عامة، بحث الأشخاص عبر Apollo عند وجود API key، دمج الملفات، إزالة التكرار، تقارير وتصدير.
المرحلة 2 — تحسين الجودة: اختبارات تحقق إضافية، فلاتر أكثر تفصيلًا، حفظ عمليات البحث والتحميلات في قاعدة بيانات خاصة.
المرحلة 3 — موصلات مزودي البيانات: إضافة Lusha وKaspr أو غيرهما واحدًا تلو الآخر بعد التحقق من API الرسمي، الصلاحيات، الأسعار، وشروط إعادة الاستخدام.
المرحلة 4 — مصادر الشركات: إثراء بيانات الشركة من مواقعها الرسمية ودلائل أعمال تسمح شروطها بالاستخدام، مع احترام تعليمات المصادر وحدود الطلبات.
المرحلة 5 — تجهيز العمل التجاري: مشروعات منفصلة لكل عميل، صلاحيات مستخدمين، سجلات تدقيق، سياسة احتفاظ وحذف، تقارير عميل، وربط CRM.
المرحلة 6 — SaaS مدفوع: تسجيل دخول، قاعدة بيانات مستضافة، حصص استخدام، فواتير ودفع، مراقبة التكاليف وأمان الإنتاج. هذه المرحلة تحتاج تصميمًا واختبارًا وخدمات استضافة إضافية وليست مشمولة في هذه النسخة.

تنبيه: لم يتم اختبار الطلبات الحية إلى Apollo/Findymail دون مفاتيح API صالحة. تمت مراجعة بناء الملف وتجربة منطق دمج البيانات والتكرارات وإنشاء ملف Excel محليًا؛ يجب اختبار تكاملات المزود بمفتاحك وعلى عدد صغير أولًا.
